# 世界存档设计（P1-P4）

> 从「一堆按角色分的会话」改成「一个持续的存档，里面有场景、在场者、主线和情报」。
> 本文是这次改造的契约：先定数据模型与规则，再分四阶段实现。

## 一、核心概念

```
存档 save（一条世界线，可多周目）
  └── 场景 scene（酒馆 / 后巷 / 牢房 —— 一个持续会话）
        ├── 在场者 presence（谁在、第几轮来的、为什么走）
        ├── 私聊 private（把某人拉到一个只有你们的地方）
        ├── 主线 quest → 章节 → 节拍 beat
        ├── 情报 clue（你掌握的事，可回忆）
        └── 好感 affinity（每个角色对你的态度）
```

**一句话**：世界是持久的，人是会走动的，信息是有代价的。

## 二、数据模型

| 表 | 关键字段 |
|---|---|
| `saves` | `id` `name` `chapter` `created_at` |
| `scenes` | `id` `save_id` `name` `place` `kind`(public/private) `created_at` |
| `presence` | `scene_id` `character_id` `entered_turn` `left_turn` `reason` `busy_with` |
| `affinity` | `save_id` `character_id` `value` `last_reason` `unlocked`(JSON 数组) |
| `quests` | `id` `save_id` `title` `chapter` `goal` `status` `clue_needed` |
| `clues` | `id` `save_id` `content` `source` `source_turn` `known_at` |
| `beats` | `id` `save_id` `at_turn` `condition` `title` `content` `sets_clue` `affinity_delta` `presence_change` |
| `messages` | 复用现有表，加 `scene_id`、`whisper`（bool） |

`condition` 是一个小表达式，支持：

```
affinity(月灯老板) >= 60
and presence(夜巡人)
and clue(通缉令)
and turn >= 6
and player_said(那晚)
```

实现上不做通用解析器：用**结构化字段**表达（`minAffinity` / `requirePresence` / `requireClue` / `atTurn` / `said` 数组），
比写一门小语言划算得多，也更好校验。

## 三、可达性：能不能找某个人

私聊之前先判断**这个人现在能不能联系上**：

| 状态 | 判定 | 玩家看到的反馈 |
|---|---|---|
| **在场** | `presence` 里有他且 `left_turn IS NULL` | 可以直接走过去说话 |
| **在忙** | 在场但 `busy_with` 非空（在擦杯子 / 在巡街） | 「他手上正忙着，未必有空理你」 |
| **已离开** | `left_turn` 有值 | 「他已经走了 —— 你可能得等下一次遇见」 |
| **不在场** | 该场景从没出现过 | 不在可见范围，列表里不显示 |

**硬规则**：联系不上就是联系不上。不提供"发消息"这种抄近道的方式 ——
否则"在场/离开"就失去意义，世界又变回通讯录。

## 四、私聊与地点

私聊有两条路，代价不同：

1. **就地低声说（whisper）**：不换场景，但**同场的其他人有机会听到**
2. **换私密场景**：把人带到后巷/账房，外人听不到，但**离开会被注意到**（可能引发 beat：「他看见你们出去了」）

私聊场景是 `scenes` 里 `kind = private` 的一行，参与者 = `presence` 里两个人。

## 五、偷听

同场且有第三者在场时，你的私聊内容**可能被听到**。判定顺序：

| 因素 | 影响 |
|---|---|
| 你说得小声（`whisper = true`） | 被听到概率大幅下降 |
| 距离（场景属性 `closeness`：嘈杂酒馆 0.3、安静后巷 0.7） | 越安静越容易听到 |
| 偷听者的性格（`curious` 标记：话痨老板/爱打听的诗人） | 更容易凑过来 |
| 偷听者当前在忙 | 更容易漏掉 |

**命中后会发生什么**（不是简单提示"被听到了"）：

- 生成一句**偷听者的反应**（插入到对话流，标注"（他听见了）"）
- 若内容敏感（涉及他的秘密/秘密关键词命中）→ **好感下降** + 解锁新 beat
- 该情报**记进偷听者的认知**（本场后续对话里他会知道这件事）

`whisper` 命中失败（没人听到）时给玩家一个**确定的反馈**：「没人注意到」——
需要这个反馈，否则玩家永远不确定自己有没有被听到。

## 六、好感度

每轮结束对**你的表现**打分，写入 `affinity`：

```
delta ∈ [-5, +5]，附带一句理由（存 last_reason，界面上显示）
触发方式：单独一次小请求（可关闭），失败则按规则给固定值，不阻塞主回复
阈值：
  >= 60  他会主动松口（可能给情报）
  <= 20  冷处理：只答必要的话，不主动推进
解锁：阈值点上的 beat 写进 affinity.unlocked，不会重复触发
```

## 七、主线与情报本

**主线**：`quests` 一章一条，章节推进靠 beat 的 `clue_needed` 与 `affinity` 达成。
界面左侧常驻「第二章 · 那张通缉令」，下方是当前目标。

**情报本**：`clues` 全量列出，每条可展开看「在哪一轮、谁说的、原话」。
这是"方便回忆"的落点 —— 不靠翻聊天记录。

## 八、界面形态

```
┌──────────────┬────────────────────────────────┬──────────────┐
│ 主线         │ 对话流                          │ 情报本       │
│ 第二章       │  ┌ 在场：老板 · 夜巡人 · 猫      │ ① 刽子手旧事 │
│ 目标：找到   │  ├ 老板：……                      │ ② 少了一个人 │
│ 通缉令       │  ├ 你（低声）：……                │              │
│              │  └ 夜巡人（他听见了）：……        │ 好感         │
│ 场景：酒馆   │                                │ 老板 ███ 62  │
│              │ [说话][行动][低声][旁白][场外]    │ 夜巡 ██ 18   │
└──────────────┴────────────────────────────────┴──────────────┘
```

输入方式在原有五种上加 **低声**，它就是「不会被所有人听到的说话」。

## 九、分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1** | 存档 + 场景 + 在场者；旧会话迁成「单场景」 | 一个酒馆，人来人往，@ 不在场的人会被告知他不在 |
| **P2** | 可达性 + 私聊场景 + 低声 + 偷听 | 能把人拉到后巷低声说话，第三者有概率听到并作出反应 |
| **P3** | 好感度 + 阈值解锁 | 老板会因为你做过的事改变态度 |
| **P4** | 主线章节 + 情报本 UI + 示例主线 | 打开就有一条能玩的主线 |

**旧数据迁移**：现有 `conversations` 每一条迁移成一个 `scene`（`kind=private`，成员 = 该角色），
消息挂到对应场景上，不丢任何记录。

## 十、不做什么（避免又变成聊天软件）

- 不做"给不在场的人发消息"
- 不做"随时传送"（换场景要花一轮，且有人会注意到）
- 不做纯数值的"送礼加好感"（好感只来自对话中的表现）
